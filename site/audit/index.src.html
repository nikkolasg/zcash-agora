Recount it yourself

You do not have to trust our number. The log is public, the result is a function of it and of the drand beacon, and the tool that checks everything is the same one we run.

What there is to check

  • The log: every checkpoint's signature under the pinned log key, and the Merkle consistency between checkpoints.
  • Every registration: its signature, its freshness, the passport proof against the registry's rule and ZKPassport's certificate registry, the uniqueness of the passport identifier, the tree positions and roots.
  • Every ballot: the root it proved against, the one-ballot rule, the zero-knowledge proof against a verification key you built yourself.
  • Every refusal: the reason, recomputed.
  • The tally: the drand beacon under the chain's public key, every opening against its commitment, the void list, the values.
  • The relays: every message a relay holds was judged by the ingest (no withholding).
  • The timestamps: every checkpoint's OpenTimestamps proof against Bitcoin block headers.

The quick way

git clone --recursive https://github.com/lanterne-labs/zcash-agora
cd zcash-agora && (cd isoloir && cargo build --release -p isoloir)
export ISOLOIR_BB=$(npm root -g)/@aztec/bb.js/build/$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')-$(uname | tr A-Z a-z | sed 's/darwin/macos/')/bb
scripts/audit.sh

Exit code 0 and no PROBLEM line is a clean recount. The script reads the mirror through jsDelivr by commit, the three relays, and Bitcoin headers from public explorers. It needs Rust, node 22, bb 5.0.0 (from npm i -g @aztec/bb.js@5.0.0), and about ten minutes for a poll of a few thousand ballots. Release binaries of the isoloir command are on the releases page if you would rather not build.

The thorough way: build the circuit yourself

The audit verifies ballots against a verification key. By default it uses the one on the mirror; a thorough auditor rebuilds it and refuses ours. You need nargo 1.0.0-beta.22 and bb 5.0.0:

cd isoloir
isoloir circuits choice4_tlock_linked_d20 --mirror ../my-circuits
# prints: choice4_tlock_linked_d20 0x33147e4950bdaa207d0123bef10466cb79c642cc78e70b4f51a6f251cc26c229
cd .. && CIRCUITS=./my-circuits/circuits scripts/audit.sh

The hash must equal the one the poll names in ledger/polls/1.json. If it does not, say so loudly.

Opening the ballots yourself

You do not need us to produce the result either. After the close, any machine can fetch the beacon and open every ballot:

isoloir authority --mirror https://cdn.jsdelivr.net/gh/lanterne-labs/zcash-agora-mirror@main \
  --circuits ./my-circuits/circuits --zkverifier isoloir/zkverifier/verify.mjs \
  --log-key "<the log key>" --drand https://api.drand.sh --nostr-key <any Nostr key> --once

It verifies the whole log first, then posts a tally through the relays. The ingest checks every opening before logging it. If your tally differs from ours, one of us is wrong and the log says who.

Reading the data by hand

The mirror is a plain directory (repository):

checkpoint.txt             the latest signed note
checkpoints/<n>.txt        every note
entries/<n>.json           the entries of checkpoint n: [{seq, kind, body}]
stamps/<n>.ots             its OpenTimestamps proof
setup/ledger.json          the ledger, the registries, the polls, with inclusion proofs
registries/1/leaves/       the registry tree's leaves
polls/1/tallies/latest.json  the result, with the beacon and the void list
circuits/<name>/vk          the verification key the ingest uses

Every file is what the log holds, with the proof that it is. The formats are in isoloir's SPEC.md §15.

Your own receipt

When you vote, your browser keeps the signed acknowledgement that names the checkpoint your ballot will be in, and checks the log for it. If the ballot is missing, the browser posts a complaint through the relays, with the acknowledgement; anyone can judge it, and only the ingest's key can have signed it. The vote page shows this check under "receipt".
